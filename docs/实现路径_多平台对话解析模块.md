# 多平台 LLM 对话记录解析模块 — 实现路径

> 目标：将任意一家 LLM 提供商（ChatGPT / Claude / Gemini / DeepSeek / Qwen / GLM / Kimi / Grok / Mistral）导出的对话记录，统一解析为格式一致的中间数据结构，供下游 Worklog Agent 消费。
>
> 最终制品形态：**`Adapter Core (Python 库)` → `CLI + SKILL.md` → `MCP Server`** 三层渐进包装，不同 vibe coding 工具按需选择调用方式。

---

## 0. TL;DR

| 维度 | 决策 |
|---|---|
| **架构范式** | Adapter Pattern + Pydantic v2 强类型（参考 echomine + LobeChat） |
| **统一中间格式** | 自定义 `UnifiedSession` / `UnifiedMessage`，融合 LobeChat 字段 + Big-AGI Fragment + ShareGPT 兼容回退 |
| **现有轮子使用策略** | ChatGPT ZIP/媒体走 `temnoon/openai_export_parser`；Claude/Gemini/Grok/Mistral 走 `llm-logparser`；DeepSeek/Qwen/GLM/Kimi 自写薄适配器 |
| **国产模型数据采集** | 网页端"导出对话"按钮的 JSON（DeepSeek/Kimi 已有）；Qwen/GLM 走 userscript 油猴脚本（参考 `claude-sharegpt-exporter`） |
| **CLI 框架** | `typer`（基于类型注解，与 Pydantic 风格一致，文档自动生成） |
| **MCP 实现** | 官方 `mcp` Python SDK（`FastMCP` 装饰器风格，零样板暴露工具） |
| **落库** | SQLite（WAL 模式），按 `provider + session_id` 去重，按 `date(created_at)` 索引 |
| **保留旧能力** | 现有 `parse_gemini_html` + `ClusteringStrategy` 不动，新模块作为前置流水线注入 |

**分三阶段交付**（每阶段独立可用，本期只做纯文字对话，不涉及图片/媒体归档）：

```
Phase 1 (4-5 天)  Schema + ChatGPT + Gemini 两个 adapter + CLI 可用
Phase 2 (2-3 天)  SKILL.md + 与现有 clustering 衔接 + 其他平台预留接口
Phase 3 (2-3 天)  MCP 包装 + 端到端测试
```

**本期范围**（明确）：
- ✅ 实现：OpenAI ChatGPT（`conversations.json` 裸 JSON，不走 ZIP+媒体）、Google Gemini（HTML 导出）
- ⏸️ 预留接口不实现：xAI Grok / Qwen / GLM / Kimi / DeepSeek / MiniMax / Mistral / Claude
  - BaseAdapter 抽象 + REGISTRY 注册表都已就位，后续每个 adapter 只需 ~80 行即可接入

### 1.2 关键设计决策

**决策 1：统一中间格式自定义，而非直接复用 ShareGPT**

ShareGPT V3 虽然是事实标准，但**丢失元数据**（无 timestamp / model / token usage / reasoning）。Worklog 场景必须按时间归集，所以采用自定义 `UnifiedMessage`，但保留 `content: str` 字段做 ShareGPT 兼容回退（一行代码可降级导出）。

**决策 2：现有轮子用「包装」而非「直依赖」**

`llm-logparser` Star 极少（社区验证度低），直接 `import` 会让项目暴露在它的稳定性风险下。采用 **Adapter 内部包装** 模式：

```python
class ChatGPTAdapter(BaseAdapter):
    def parse(self, path: Path) -> list[UnifiedSession]:
        # 优先尝试自写的轻量解析（结构稳定）
        # 仅在遇到 ZIP + 媒体归档场景才 fallback 到 temnoon
```

这样轮子挂了，替换实现只需改一个文件，不影响 Schema 与 CLI。

**决策 3：国产模型数据源分两档**

| 档位 | 平台 | 数据源 | 实现成本 |
|---|---|---|---|
| A | DeepSeek / Kimi | 网页端「导出对话」按钮产出的 JSON | 低（~80 行/平台） |
| B | Qwen / GLM | 无官方导出，需 userscript 注入采集 | 中（~150 行 Python + 100 行 JS） |

userscript 模式参考 `claude-sharegpt-exporter`：注入页面后拦截 XHR 响应、提取 conversation JSON、打包下载。**这部分先在 Phase 2 末尾交付**，不阻塞主干。

**决策 4：CLI 与 MCP 共用同一 `pipeline.run()` 入口**

避免双份逻辑。MCP 工具只是 CLI 命令的薄包装：

```python
# cli.py
@app.command()
def parse(input_path: Path, provider: str = "auto"):
    sessions = pipeline.run(input_path, provider=provider)
    ...

# mcp_server.py
@mcp.tool()
def parse_conversations(input_path: str, provider: str = "auto") -> str:
    sessions = pipeline.run(Path(input_path), provider=provider)
    return json.dumps([s.model_dump(mode="json") for s in sessions], ensure_ascii=False)
```

## 2. 核心模块详设

### 2.1 Unified Schema（统一中间格式）

融合 LobeChat（字段最完备）+ Big-AGI（Fragment 系统）+ ShareGPT（content 回退）：

```python
# src/unified_schema.py
from pydantic import BaseModel, Field
from typing import Literal, Optional
from datetime import datetime

Provider = Literal[
    "openai", "anthropic", "google", "xai", "mistral",
    "deepseek", "qwen", "glm", "kimi", "unknown"
]

class Fragment(BaseModel):
    """Big-AGI 风格 fragment — 一条消息可由多个 part 组成"""
    kind: Literal["text", "image", "tool_call", "tool_response", "code", "error", "reasoning"]
    text: Optional[str] = None
    mime_type: Optional[str] = None
    file_path: Optional[str] = None            # 媒体文件本地相对路径
    tool_name: Optional[str] = None
    tool_args: Optional[dict] = None
    tool_result: Optional[str] = None

class TokenUsage(BaseModel):
    prompt_tokens: int = 0
    completion_tokens: int = 0
    total_tokens: int = 0
    cost_usd: Optional[float] = None

class UnifiedMessage(BaseModel):
    id: str
    session_id: str
    role: Literal["user", "assistant", "system", "tool"]
    content: str                               # ShareGPT 兼容回退
    fragments: list[Fragment] = []             # 多模态结构化内容
    provider: Provider = "unknown"
    model: Optional[str] = None
    parent_id: Optional[str] = None            # 树状对话
    thread_id: Optional[str] = None            # 分支对话
    usage: Optional[TokenUsage] = None
    reasoning: Optional[str] = None            # 思维链（o1/Claude thinking）
    tools: Optional[list[dict]] = None
    trace_id: Optional[str] = None             # 厂商 trace ID
    upstream_ref: Optional[str] = None         # 厂商原始 message ID
    created_at: datetime
    updated_at: Optional[datetime] = None
    source: Literal[
        "chatgpt_export", "claude_export", "gemini_export",
        "deepseek_export", "qwen_export", "glm_export", "kimi_export",
        "api", "manual"
    ] = "manual"

class UnifiedSession(BaseModel):
    id: str
    title: Optional[str] = None
    provider: Provider
    model: Optional[str] = None                # 会话级模型（如整段都是 gpt-4o）
    messages: list[UnifiedMessage]
    created_at: datetime
    updated_at: Optional[datetime] = None
    source: str
    raw_metadata: Optional[dict] = None        # 原始导出元数据保留（去重/审计用）
```

**字段完备性度量**（用于评估对原始信息的保留度）：

$$
\text{Retention}(adapter) = \frac{|\text{fields populated}|}{|\text{UnifiedMessage fields}|} = \frac{\sum_{i} \mathbb{1}[f_i \neq \text{null}]}{N_{\text{fields}}}
$$

目标：主流平台 Retention ≥ 0.6，国产平台 ≥ 0.4（无 usage 等字段时允许为空）。

### 2.2 Adapter 抽象

```python
# src/adapters/base.py
from abc import ABC, abstractmethod
from pathlib import Path

class BaseAdapter(ABC):
    """所有平台 adapter 的统一接口"""

    provider: str                             # 子类必填，如 "openai"
    supported_extensions: tuple[str, ...] = (".json", ".jsonl", ".html", ".zip")

    @abstractmethod
    def parse(self, path: Path) -> list[UnifiedSession]:
        """解析导出文件，返回统一会话列表"""
        ...

    def detect(self, path: Path) -> float:
        """
        格式探测置信度 [0, 1]。
        - 1.0: 文件特征完全匹配（如 ChatGPT 的 conversations.json 顶层有 'title' + 'mapping'）
        - 0.5: 仅扩展名匹配
        - 0.0: 明确不匹配
        pipeline 选取置信度最高的 adapter。
        """
        return 0.0
```

`detect()` 是关键：让用户不需要传 `--provider`，pipeline 自动选 adapter。这是替代现有 `parse_conversation` 硬路由的核心机制。

### 2.4 Pipeline 解析流水线

```python
# src/pipeline.py
from pathlib import Path
from src.adapters import REGISTRY  # 所有已注册 adapter

def detect_provider(path: Path) -> tuple[BaseAdapter, float]:
    """返回 (最佳 adapter, 置信度)。无任何 adapter > 0.3 时抛错。"""
    scored = [(a, a().detect(path)) for a in REGISTRY]
    scored.sort(key=lambda x: x[1], reverse=True)
    if not scored or scored[0][1] < 0.3:
        raise ValueError(f"无法识别文件格式: {path}")
    return scored[0]

def run(
    input_path: Path,
    provider: str = "auto",
    out_format: Literal["json", "jsonl", "markdown"] = "json",
    outdir: Path = None,
    timezone: str = "Asia/Shanghai",
    group_by_date: bool = False,
) -> list[UnifiedSession]:
    """
    完整流水线: detect → parse → normalize(tz) → (optional) group by date → export
    """
    # 1. 选 adapter
    if provider == "auto":
        adapter, confidence = detect_provider(input_path)
    else:
        adapter = next(a for a in REGISTRY if a.provider == provider)()
        confidence = 1.0

    # 2. 解析
    sessions = adapter.parse(input_path)

    # 3. 时区归一化
    sessions = normalize_timezone(sessions, timezone)

    # 4. (可选) 按天分组 — 兼容下游 clustering.py 的 DailyConversation 输入
    if group_by_date:
        return group_sessions_by_date(sessions)

    # 5. 导出
    if outdir:
        export(sessions, outdir, out_format)

    return sessions
```

```markdown
# AI Worklog Parser Skill

## 何时使用
当用户提供 LLM 平台导出文件（JSON/HTML）并希望转为统一工作日志格式时。
本期支持 ChatGPT 和 Gemini 两平台；其他平台（Claude/Grok/DeepSeek/Qwen/GLM/Kimi/MiniMax）adapter 接口已预留，待实现。

## CLI 调用约定

### 1. 解析单个文件
\`\`\`bash
aiworklog parse <input_path> [--provider auto] [--format json] [--outdir ./output]
\`\`\`

### 2. 批量解析
\`\`\`bash
aiworklog parse-batch <input_dir> --outdir ./output
\`\`\`

### 3. 与 Worklog 流水线衔接
\`\`\`bash
# Step 1: 解析为统一格式
aiworklog parse chatgpt.zip -o ./parsed --group-by-date

# Step 2: 喂给 clustering（下游已有）
python -m src.clustering ./parsed
\`\`\`

## 输出格式契约
统一输出 `UnifiedSession[]`，单文件 JSON 数组。每条消息含：
- `role`: user/assistant/system/tool
- `content`: 纯文本（ShareGPT 兼容）
- `provider` + `model`: 厂商与模型分离
- `created_at`: ISO 8601 时间戳（已转 Asia/Shanghai）
- `fragments[]`: 多模态内容（文本/图片/工具调用/思维链）

## Agent 决策规则
1. 用户给文件路径 → 调 `parse`
2. 用户给目录 → 调 `parse-batch`
3. 用户未指定 provider → 用 `auto`（pipeline 自动探测）
4. 输出文件路径必须返回给用户确认
```

## 5. 关键代码骨架

### 5.1 ChatGPT Adapter（核心难点）

```python
# src/adapters/chatgpt.py
import json
import zipfile
from pathlib import Path
from datetime import datetime, timezone
from src.adapters.base import BaseAdapter
from src.unified_schema import (
    UnifiedSession, UnifiedMessage, Fragment, Provider
)

class ChatGPTAdapter(BaseAdapter):
    provider: str = "openai"
    supported_extensions = (".json", ".zip")

    def detect(self, path: Path) -> float:
        if path.suffix == ".zip":
            try:
                with zipfile.ZipFile(path) as zf:
                    if "conversations.json" in zf.namelist():
                        return 0.95
            except zipfile.BadZipFile:
                return 0.0
        if path.suffix == ".json":
            try:
                data = json.loads(path.read_text(encoding="utf-8"))
                if isinstance(data, list) and len(data) > 0:
                    first = data[0]
                    if "title" in first and "mapping" in first:
                        return 0.95
            except Exception:
                return 0.0
        return 0.0

    def parse(self, path: Path) -> list[UnifiedSession]:
        # 1. 读取 conversations.json（支持 ZIP 或裸 JSON）
        if path.suffix == ".zip":
            with zipfile.ZipFile(path) as zf:
                with zf.open("conversations.json") as f:
                    raw = json.load(f)
        else:
            raw = json.loads(path.read_text(encoding="utf-8"))

        sessions = []
        for conv in raw:
            session = self._parse_one_conv(conv)
            if session:
                sessions.append(session)
        return sessions

    def _parse_one_conv(self, conv: dict) -> UnifiedSession | None:
        conv_id = conv.get("id") or conv.get("conversation_id")
        if not conv_id:
            return None

        # ChatGPT 导出的 mapping 是树状结构，根节点 id 通常为 "ROOT"
        mapping = conv.get("mapping", {})
        messages: list[UnifiedMessage] = []

        for node_id, node in mapping.items():
            msg = node.get("message")
            if not msg:
                continue

            role = msg.get("author", {}).get("role", "unknown")
            if role not in ("user", "assistant", "system", "tool"):
                continue

            content = msg.get("content", {})
            text_parts = []
            fragments = []

            # content.parts 可能是字符串数组或对象数组
            # 本期只处理文本；图片/代码 part 暂时跳过（Fragment 字段保留待后续扩展）
            for part in content.get("parts", []):
                if isinstance(part, str):
                    text_parts.append(part)
                elif isinstance(part, dict):
                    ct = part.get("content_type")
                    if ct == "text":
                        text_parts.append(part.get("text", ""))
                    # image_asset_pointer / code 等非文本 part 本期跳过
                    # 后续扩展时在此填 fragments.append(Fragment(...))

            # 思维链 (o1/o3 系列) — 本期保留，属于纯文本范畴
            if msg.get("reasoning"):
                fragments.append(Fragment(kind="reasoning", text=msg["reasoning"]))

            created = msg.get("create_time")
            created_dt = (
                datetime.fromtimestamp(created, tz=timezone.utc)
                if created else datetime.now(timezone.utc)
            )

            messages.append(UnifiedMessage(
                id=node_id,
                session_id=conv_id,
                role=role,
                content="\n".join(text_parts),
                fragments=fragments,
                provider="openai",
                model=msg.get("metadata", {}).get("model_slug"),
                created_at=created_dt,
                source="chatgpt_export",
                upstream_ref=msg.get("id"),
            ))

        if not messages:
            return None

        messages.sort(key=lambda m: m.created_at)
        return UnifiedSession(
            id=conv_id,
            title=conv.get("title"),
            provider="openai",
            model=messages[-1].model,
            messages=messages,
            created_at=messages[0].created_at,
            updated_at=messages[-1].created_at,
            source="chatgpt_export",
            raw_metadata={"weight": conv.get("weight")},
        )
```

### 5.3 与下游 clustering 衔接

```python
# src/bridge.py
from src.unified_schema import UnifiedSession
from src.models import DailyConversation, ConversationMessage
from collections import OrderedDict

def unified_to_daily(sessions: list[UnifiedSession]) -> list[DailyConversation]:
    """UnifiedSession → DailyConversation，供现有 clustering.py 消费"""
    grouped = OrderedDict()
    for sess in sessions:
        for msg in sess.messages:
            date_str = msg.created_at.strftime("%Y-%m-%d")
            grouped.setdefault(date_str, []).append(
                ConversationMessage(role=msg.role, content=msg.content, date=date_str)
            )
    return [DailyConversation(date=d, messages=m) for d, m in grouped.items()]
```

下游 `clustering.py` 零改动，只是输入来源从 `parse_gemini_html` 换成 `unified_to_daily(pipeline.run(...))`。

## 6. 风险与权衡

### 6.1 依赖 llm-logparser vs 自写

| 方案 | 优点 | 风险 |
|---|---|---|
| 直接 `import llm_logparser` | 省 80 行/平台 | Star 极少，API 可能 breaking change；AGPL 风险需核查（实为 MIT） |
| 自写 + 仅备用 | 完全可控；国产模型本就得自写 | 多花 1-2 天 |
| **混合**：自写主流，llm-logparser 作 fallback | 主路径稳定，异常时多一层保险 | 略复杂 |

**采用混合**：自写为主，`llm-logparser` 作为 `optional-dependencies`，仅在自写解析失败时 try-import 调用。

### 6.2 国产模型数据源不稳定

Qwen / GLM 网页端结构可能变化，userscript 会失效。**对策**：
- userscript 版本号 + 失效检测（采集时校验关键字段存在）
- 文档明确标注「数据源依赖网页端结构，平台改版需更新脚本」
- 优先鼓励用户用 API 模式（如果有 API key，写 `QwenAPIAdapter` 直接走官方 SDK）

### 6.3 Schema 演进

Pydantic v2 自带版本兼容（`model_config = ConfigDict(extra="allow")`），新字段可平滑加入。落库 SQLite 用 JSON 列存 `raw_metadata`，schema 不变也能存新增字段。

### 6.4 MCP vs CLI 取舍

| 场景 | 推荐调用方式 |
|---|---|
| WorkBuddy Skill / Cursor / Claude Desktop | MCP（结构化输入输出，Agent 友好） |
| 命令行脚本 / CI / shell pipeline | CLI（管道友好，可组合） |
| Python 项目内集成 | 直接 import `src.pipeline` |

**三层同源**：MCP 和 CLI 都调 `pipeline.run()`，行为一致，不存在功能割裂。
